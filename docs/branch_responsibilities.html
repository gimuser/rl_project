Responsabilités par branche

Ce document explique à chaque membre son périmètre, ses restrictions et ses livrables attendus.

Pipeline global du système

1. Extraction des données
data/ + backend/app/data_pipeline/loader.py → nettoyage et préparation.
2. Préparation des features
backend/app/data_pipeline/feature_engineering.py → encoder/normalizer/validator.
3. Construction de l’état
backend/app/environment/state_builder.py + backend/app/models/state.py + observation_space.
4. Simulation SOC & environnement
backend/app/simulation/alert_generator.py → incident_generator.py → soc_simulator.py → gym_env.py.
5. Prise de décision de l’agent
backend/app/rl_agent/policy.py + ppo.py / dqn.py / a2c.py + trainer.py + inference.py.
6. Récompense & retour d’expérience
backend/app/reward/reward_function.py + severity/analyst/latency/false_positive rewards.
7. Observation, API & évaluation
backend/app/api/ → services → monitoring → evaluation/report.py.
Branche feature/rl-agent

Responsable : Développeur 1

Répertoires : backend/app/rl_agent/

Responsabilités : PPO, DQN, A2C, policy, trainer, replay buffer, checkpoints, inference, optimisation.

Restrictions : ne pas modifier les modules métier non liés au RL.

Livrables : modèles, entraînement, documentation technique.

Branche feature/data-pipeline

Responsable : Développeur 2

Répertoires : backend/app/data_pipeline/, data/, scripts/preprocess.sh, scripts/seed_database.py

Responsabilités : chargement, nettoyage, validation, préparation des datasets.

Restrictions : ne pas toucher au code RL.

Livrables : datasets prêts à l’emploi, scripts de préparation.

Branche feature/environment

Responsable : Développeur 3

Répertoires : backend/app/environment/, backend/app/simulation/, backend/app/models/

Responsabilités : états, actions, épisodes, reset, simulation SOC.

Restrictions : ne pas modifier PPO ou DQN.

Livrables : environnement RL et simulation cohérents.

Branche feature/reward-system

Responsable : Développeur 4

Répertoires : backend/app/reward/

Responsabilités : reward function, analyst reward, severity reward, latency reward, false positive reward.

Restrictions : ne pas modifier l’environnement ni le code RL.

Livrables : logique de récompense documentée et testée.

Branche feature/backend-api

Responsable : Développeur 5

Répertoires : backend/app/api/, backend/app/services/, backend/app/schemas/, backend/main.py, backend/app/config/

Responsabilités : FastAPI, endpoints, validation, intégration.

Restrictions : ne pas modifier PPO.

Livrables : API propre, documentée et sécurisée.

Branche feature/database-monitoring

Responsable : Développeur 6

Répertoires : backend/app/database/, backend/app/monitoring/, logs/

Responsabilités : stockage, logging, métriques, TensorBoard, monitoring.

Restrictions : ne pas modifier le code RL.

Livrables : observabilité et traçabilité du système.

Branche feature/frontend

Responsable : Développeur 7

Répertoires : frontend/

Responsabilités : dashboard, React, graphiques, statistiques, UI, consommation API.

Restrictions : ne jamais accéder directement à la base de données.

Livrables : interface utilisateur fonctionnelle et élégante.
